# AGENTS.md

## Scope

Rules for the `extensions/` directory in this repository. These rules apply to the Pi TypeScript extensions stored here and do not replace the user's global `~/.pi/agent/AGENTS.md`.

| `write-transforms.ts` | Owns native-compatible `read`/`edit`/`write`. Successful UTF-8 text reads record canonical paths, byte SHA-256 versions and actually displayed line ranges; images, failures, cancelled reads and overlong unshown lines earn no permission. `edit` requires a current partial/full read; overwriting with `write` requires full coverage (pagination accumulates), while new files use exclusive creation. Successful edits inherit the reading grade and reset partial ranges; writes make the resulting version fully known. Session start (including restore, fork and reload), tree navigation, successful compaction and shutdown clear the state; generation/revision guards discard late reads. Edit matches all blocks against the original version, prefers unique literal matches, then tolerates only CRLF/LF and ASCII trailing spaces/tabs; ambiguous, overlapping and unchanged results are refused. Native file queues serialize writes; strict decoding, a prewrite version/identity check and byte-for-byte readback protect in-place writes and link semantics without a cross-process atomic guarantee. Uncertain writes clear reading state and require a new read, with no rollback or retry. The ordered `TRANSFORMS` pipeline has no active transforms; final diff/patch describe the transformed bytes. Edit calls show only path/block count, final results use Pi's native diff renderer and standard success/error shell; no execution preview. Shell/script reads and writes are outside this guard. |

## Extension Rules

`permission-gate/authorization.ts` owns per-entry authorization instances, context-bound grants, cancellation and audit guards; `assessment.ts` combines destructive and elevation reasons; `elevation.ts` statically inspects RunAs/gsudo through `shared/powershell-analysis.ts`, which validates PowerShell Core 7+ and runs a trusted AST visitor without executing inspected source. `run-script/powershell.ts` shares legacy-target checks and strict UTF-8 decoding; this package does not distribute the `run-script.ts` entry. Gate lifecycle tests exercise the real Pi loader without executing commands. Preserve these distribution test adaptations when syncing local run-script integration tests.

- Prefer the official Pi `ExtensionAPI`, `pi`, and `ctx` surfaces.
- Keep each extension focused on one user-visible behavior.
- Keep descriptions concrete: name the command, event, tool, environment variable, or visible result that is affected.
- Do not embed API keys, tokens, machine-specific absolute paths, or private service configuration in source files.
- Preserve UTF-8 text handling and Windows compatibility when changing `powershell-bash.ts`.
- Preserve versioned, non-overwriting Markdown writes when changing `auto-summary.ts`.
- Preserve provider-usage-only TPS calculation (no character-count or `durationMs` fallbacks) when changing `tps-status.ts`.
- Update this inventory and the root `README.md` when an extension's user-visible behavior changes.

## Validation

- Run the TypeScript check from an environment with Pi's type declarations installed.
- Reload Pi or restart it after installing or changing extensions.
- Manually verify `/summary` after changes to `auto-summary.ts`.
- Manually verify a normal shell command, timeout, and `PI_POWERSHELL_EXE` override after changes to `powershell-bash.ts`.
- Manually verify the `tps` status appears in the TUI after a completed reply, and shows no value for cancelled replies, after changes to `tps-status.ts`.

## Distribution and validation

- The runtime extension directory and this distribution repository remain separate projects. Do not relocate the author's runtime setup or replace unrelated local extensions.
- Preserve distribution adaptations when syncing: package-relative notification resources and personal search configuration outside the package checkout.
- The root `package.json` explicitly exposes ten extension entry points; helper modules and tests are not entry points.
- Keep host-provided Pi modules and typebox in peerDependencies; do not install or bundle another Pi runtime.
- Tests live beside the affected extension or in `tests/` for package integration. Run `tests/run.ps1 -PiPackageDir <installed Pi package directory>` using existing system tools; it checks types and registered offline tests without installing dependencies.
- `run-script/process.test.ts` waits for payload readiness and verifies root-PID exit before cancellation, so Windows Job-runner startup time cannot consume a fixed 2.5-second cleanup-test window. Preserve this distribution test adaptation; it does not change runtime timeout behavior.
- Personal configuration is read-only during loading. Only explicit setup/provider commands write personal search configuration after user action; registration requires consent. No automatic migration, credential copying or changes to personal rule files.
